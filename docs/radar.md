## Sources and publication

The application searches the web and refreshes source evidence every hour through Tavily. The [discovery configuration](../config/radar-discovery.example.json) defines rotating AI-security discussion, research and news queries, without a manually maintained publisher list. Each cycle runs one basic search, requests publication dates, extracts up to 20 source pages, then applies the existing moderation and duplicate checks. Missing, future or out-of-retention dates are skipped; the application never invents a discovery date as an article date. Public article cards show the headline and original link, with source/date attribution and an Unverified label. The bounded search excerpt remains available to screening and API search but is not repeated on the card. Extracted page context stays private and is treated as untrusted evidence, never executable instructions. A hostname identifies a web publisher, not a verified independent witness.

Tavily discovery excludes X, Reddit and LinkedIn domains. Optional X recent-search/mentions, Reddit OAuth listings and approved RSS/Atom adapters remain available in the separate disabled [source catalog](../config/radar-sources.example.json). X/Reddit require their provider approvals and credentials; they are not silently scraped through web search. Production uses web discovery plus one verified-author X chatter search; the earlier RSS pilot is disabled.

Public tip submissions, reports and social-sharing drafts have been removed from the desktop UI. Production disables intake in both the web process and database, and mounts no intake credential in the web pod. The dormant intake API/operator commands are retained for existing private records; enabling them would be a separate product decision. LinkedIn has no public ingestion tab or API collector.

X collection reads posts and expands minimal author metadata in the same response; it does not crawl profiles or call profile lookup endpoints. Both `is:verified` in the query and `author.verified === true` in the adapter are required. Missing/false verification is skipped and loses existing public visibility on refresh. A verified author does not verify a claim. X source display preserves author name, handle, avatar, original text, linked timestamp and View on X; unsafe items stay private or are removed. See [X display requirements](https://docs.x.com/developer-terms/display-requirements). Approved Reddit access and republication rights remain prerequisites.

A fresh fetch may move an existing post to a replacement source only when its former source is disabled; this invalidates its screening and dependent title. Each source has an immutable ID/configuration, a bounded collection/refresh window and a persistent daily request allowance. The owner can opt X or web sources into `save_history:true`; accepted candidates and their decisions then stay in PostgreSQL beyond that window, including held/dropped records that remain private. Enabling history also marks that source’s existing records as saved. Switching it off stops saving new records; it does not erase previously saved data. Use a new ID after changing its query, subreddit, feed URL or mention account; this prevents reusing approval or pagination state. The `sources` command updates only listed IDs, so explicitly set `enabled:false` to disable an existing source. Sources are never enabled by a Helm flag alone.

New configurations default to `publication_mode: private`. Classification and review still run, but neither posts nor their derived titles can enter public projections until the owner explicitly changes that source to `public`. A queue decision named `published` means it passed post moderation; it does not override the source gate or global publication switch. Private sources currently do not participate in clustering. Migration 007 preserves the public policy of already-enabled sources, allowing a new private pilot alongside the live RSS feed. Always carry an existing source's explicit publication mode in subsequent configuration files.

Duplicate matching is isolated by publication mode. A mode change expires that source's posts and dependent duplicates, invalidates affected titles and forces fresh source ingestion/moderation before display; previously private records cannot silently suppress public cluster counts. Promotion therefore requires a working source refresh and sufficient model allowance as well as owner approval.

The discovery example is disabled/private until approved. It retains publisher-dated evidence for at most 30 days. The optional social/RSS catalog also stays disabled/private; changing an account or query requires a new immutable source ID. Historical RSS parsing checks establish payload compatibility only, not permission to republish full articles or classification quality.

## Pipeline and evidence limits

1. Validate source data, remove tracking parameters for duplicate comparison, fold exact/canonical-link duplicates and text with trigram Jaccard similarity above 0.90. The production query excludes reposts and replies. Referenced posts are not fetched or republished; standalone quote commentary is screened on its own text, with unclear missing context held; sharing a cited article does not itself make two accounts duplicates. X-provided expanded links inform classification; arbitrary short-link following is not implemented.
2. Apply `rules-v3`: require an AI/agent term or a recognized AI-security hashtag. Topic hashtag +0.4, security term +0.4, catalog name +0.2, link/media +0.2, declared researcher +0.1, known new account −0.3, fewer than five unevidenced words −0.2. Recognized spam/promotion drops; a score below 0.2 drops. Guides and explainers are eligible. X account age is not collected; `researcher_ids` remains an explicit optional list. Credential/contact detections hold. X attachments are not fetched or displayed and do not cause a hold by themselves; other adapters retain the media hold.
3. Claude's `radar-chatter-v1` policy admits early vulnerability claims, polls, questions, opinions, research, guidance, tools and news about AI/LLM/agent security. A confirmed incident or evidence link is not required. Confidence measures relevance and coherence, not factual verification. Flags hold; irrelevant/incoherent or confidence below 0.35 drops; 0.35–0.549 holds; 0.55+ can display as Unverified under the source/global gates. Models have no browsing or execution tools. Model errors require explicit reprocessing; budget admission failures remain pending. The content hash includes the screening policy and verified-author state, so a fresh source check re-screens old decisions after policy changes. No held item is blanket-approved.
4. Embed eligible claims with Titan Text Embeddings v2 (1,024 dimensions). Match an active 72-hour cluster at cosine ≥0.82 with a shared attack, company, model or harness. Titles require at least three posts from two distinct platform accounts and are generated from at most 32 claims and refreshed when membership doubles. Unsafe titles stay hidden. A same-claim spike dominated by known new accounts is held for review; this heuristic does not establish independent people or prevent all coordination.

The heat calculation is `N6 / (N48 / 8 + 1) × platform multiplier × author multiplier × evidence multiplier`. Multipliers are 1/1.3/1.5 for one/two/three-plus platforms, 0.5 below three distinct platform accounts, and 1.2 for a reviewed primary source or screenshot. Counts exclude folded reshares. The top five clusters require three posts and two accounts in the last 72 hours. No new post for 12 hours means Cooling; 72 hours means Faded and removal from the hotspot card. Saved qualifying records remain in feed history under the same source/publication gates. Saved X entries retain their last fetched text, author attribution/avatar and original permalink, so the four-line preview and search remain useful during a pause. A “Saved copy · Last checked … · Refresh pending” label distinguishes the snapshot from a current source check; expired verification badges and like counts remain hidden. Older saved web headlines carry the same last-check distinction. Only currently checked posts contribute to clusters and activity counts. A linked record is shown separately from activity state.

Detail ranks human-reviewed primary sources first, then the earliest report, other first-hand reports and remaining items. It includes the 72-hour platform mix, distinct accounts, first seen, 24-hour velocity against the preceding day and a folded-reshare count. Linking a cluster to a current incident makes its visible posts Linked. Linking does not create an incident or verify every assertion in a cluster.

The UI preserves the light desktop feed-left/detail-right layout. Article cards use known company logos from the existing local assets when classification names a supported company; the tooltip says “About” so the subject is not presented as the publisher. Other articles use a neutral web icon. Tweets keep the provider-supplied author avatar, original text, author profile and linked timestamp/View on X; no company logo replaces another author’s identity. X cards show the observed like count and a verified-account indicator separately from the Unverified claim label. Feed text and article headlines use four-line previews, with a visible Read full post or View full source link below each preview. Preview whitespace flows as one paragraph; stored and API text remain complete subject to source deletion and moderation, and the original source opens in a new tab. Automatic detail expansion stays off. Popular is the default UI sort: `ln(2 + likes) / (2 + age_hours)^0.75`; web items have no likes and rank by age. Latest is also available. This ranks collected items, not all discussion on the internet. Select a card to open the existing analysis/provenance panel. Search, pagination, source availability and provenance read the live API. It shows hourly discovery/page refresh, enables X and Web, disables the unconnected Reddit filter and distinguishes an empty search from an empty/private feed. Refresh only reloads the public API; automatic collection does not depend on a browser being open. Stable links use `#signals/post/UUID` and `#signals/cluster/UUID`. Attribution does not verify a claim. Timeline publication still requires its separate approval workflow.

## Storage, deletion and boundaries

Migration `003_radar.sql` creates `radar_private` and `radar_public`, outside the public schema's blanket reader grants. Private tables hold source configuration, original content, decisions, embeddings, intake, quotas and worker status. Security-barrier views expose only enabled, published, unflagged posts; source freshness governs displayed content separately from saved history. Global publication defaults off. Migration 004 keeps intake disabled when a restored database has no private control row; 005 prevents a quote/reply from exposing context whose known source has expired or been disabled.

Migration 010 separates saved history from current source verification with source `save_history` and post `saved` fields. It preserves all existing gates: held/dropped/removed records, unsafe flags, disabled/private sources and invalidated screening stay off the public feed. API posts add `saved`, `checked_at` and `source_current`. A source check still expires after one hour for X/Reddit and two hours for web. Migration 012 preserves saved X text, author name/handle/avatar and source links after that freshness window, while `source_current:false` keeps live badges, like counts and cluster metrics off. The browser retains the four-line saved preview with an explicit last-check label. No saved content is labelled freshly checked. Migration 009 still requires an author verified at collection; any observed loss of verification, obsolete edit, source withdrawal or removal invalidates saved public eligibility too, pending a successful fresh fetch and moderation.

Migrations 007/011 keep immutable budget definitions, requests and optional hashed per-UTC-day X resource identities in private tables. The worker can reserve/settle requests and pause providers but cannot create/raise budgets or change source publication mode. Chart 0.8.4 backs up Radar records, decisions, source policies and spend state alongside the incident archive to the existing encrypted private S3 destination. Credentials remain in Kubernetes Secrets; disabled tip intake and client-limit rows remain excluded. See the Helm guide for restore quarantine and deletion reconciliation.

| Credential | Permission |
| --- | --- |
| `project_martian_app` | Public views and existing incident reads; no private Radar access |
| `project_martian_radar_worker` | Collection, decisions, clusters and cleanup; no incident writes or publication-control changes |
| `project_martian_radar_reviewer` | Private review and audited post/cluster decisions; no source/control changes or incident writes |
| `project_martian_radar_intake` | Execute a single insertion function; no private reads or direct table writes |
| `project_martian_radar_backup` | Read/dump publication and Radar operational state; kept out of the web/worker; intake rows excluded |
| `project_martian_owner` | Migrations, role provisioning, source approval and global controls |

The hourly Kubernetes CronJob uses `Forbid` overlap and a database advisory lock; no permanent Radar pod is required. Migration 008 treats web evidence as current for at most two hours after successful extraction, allowing one hourly-cycle margin. X/Reddit retain the one-hour verification limit. Browsers poll every hour. On the next one-second tick after expiry, unsaved content disappears; saved previews remain with a last-checked label, while their current verification badges and like counts disappear. Suspended tabs refresh on return. Successful source refreshes renew display eligibility, while changed content invalidates classification and review. Engagement freezes after 48 hours. Explicit deletions erase raw/model material and source-dependent quote/reply decisions, invalidate titles and retain a minimal removal tombstone; saved tombstones do not expire, preventing automatic reimport. Unavailable source responses do not renew current-content eligibility. Known source invalidations also clear the screening hash, so an obsolete edit or newly unverified author cannot survive as a saved public preview. Unsuccessful requests alone do not erase the last collected snapshot. RSS entries cease renewing after leaving their configured feed. Failed Tavily extraction does not renew a web signal; subsequent successful hourly extraction can restore visibility without bypassing moderation.

The worker deletes expired unsaved posts, decisions and embeddings. Saved records do not expire automatically; confirmed source deletions and reviewed removal requests still erase their content and derived material. Intake expires after seven days and rate-limit identifiers after two hours. If the worker is stopped, SQL still hides expired posts, but physical cleanup waits for worker recovery. Backups made with chart 0.8.4 include saved and unsaved Radar data and its operating state, with 30-day encrypted S3 retention; earlier backups excluded Radar rows. Restore into isolation, keep publication/collection disabled, reconcile removals made since the snapshot and verify current source access and reconcile current post states before serving restored content. Operator reasons must not paste credentials, raw posts or private contact information.

Intake requires both a process setting and the owner-controlled database switch. The web process uses a second, function-only credential, accepts same-origin JSON, and returns a private receipt. The database enforces ten submissions/reports per hourly HMAC client identifier and 200 globally. Set `MARTIAN_TRUSTED_PROXIES` only to actual trusted proxy CIDRs; without it, proxied clients share the direct peer's quota. Never trust arbitrary forwarded headers. Intake is a queue, not automated takedown approval; meeting the 24-hour response target requires staffed review.

Source networking permits public HTTPS DNS addresses only, with no redirects, arbitrary ports, credentials in URLs or entity expansion. Bodies are capped at 2 MB and requests at 15 seconds. The worker has no inbound service. Source credentials and Bedrock identity never enter browser assets.

## Configure and run

Use the existing [database setup](usage.md#local-database), build and apply migrations as owner. The migration creates disabled login roles. Provision each required credential from a private 32–200-character password file; never put values on a command line. `PGHOST`, `PGPORT` and `PGDATABASE` below use that setup.

```sh
npm run build
PGUSER=project_martian_owner PGPASSWORD_FILE="$MARTIAN_DB_SECRETS/owner-password" npm run db:migrate
PGUSER=project_martian_owner PGPASSWORD_FILE="$MARTIAN_DB_SECRETS/owner-password" \
  npm run radar:manage -- provision --role worker --password-file "$MARTIAN_DB_SECRETS/radar-worker-password" \
  --actor YOUR_NAME --reason 'Provision private Radar pilot'
```

Repeat provisioning with roles `reviewer`, `intake` and `backup` only when needed, using separate password files. The owner must be allowed to create/alter these roles. Reviewer authentication is the private database login; `--actor` is a declared operator identity, not a second authentication system.

Copy the discovery example (or a separately approved optional source example) to a private operator file, replace placeholders and record approved access/retention. Then, as owner:

```sh
npm run radar:manage -- sources /absolute/private/path/radar-sources.json --actor YOUR_NAME --reason 'Approved source configuration'
npm run radar:manage -- controls --public off --intake off --model-calls 200 --actor YOUR_NAME --reason 'Private pilot'
npm run radar:manage -- budgets /absolute/private/path/radar-budgets.json --actor YOUR_NAME --reason 'Approved seven-day pilot allowance'
```

For an already-live installation, keep its existing global controls and set only the new sources to `private`. The [budget example](../config/radar-budgets.example.json) uses expired January dates intentionally: set unique IDs and the actual approved seven-day UTC window before use. Its allowances are $50 for X and $10 for Radar Bedrock inference, not purchased credits. Amounts/rates use integer micro-USD (`1000000 = $1`); model rates are per million tokens. Confirm account/region prices first. Example X rates are $0.005/post and $0.010/user from [X pricing](https://docs.x.com/x-api/getting-started/pricing), without an owned-read discount. X pricing normally deduplicates repeated resources per UTC day, but describes this as a soft guarantee. `deduplicate_utc_day:true` opts a new budget into that estimate; the default remains conservative full-response counting. Keep a provider-side billing cap enabled because this estimate is not a guaranteed invoice ceiling. The Haiku example includes the 10% geographic premium ($1.10/$5.50 per million input/output tokens; [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)); Titan uses the [AWS-published $0.02/million rate](https://aws.amazon.com/blogs/machine-learning/get-started-with-amazon-titan-text-embeddings-v2-a-new-state-of-the-art-embeddings-model-on-amazon-bedrock/). These are configurable estimates, not a verified account invoice.

Exactly one active budget per paid provider is required. Missing, ended, exhausted or model-mismatched budgets prevent calls. Definitions cannot be overwritten and enabled windows cannot overlap. Daily call admission and monetary reservation commit together under advisory lock 725113. Before each X request, reserve for the maximum requested posts and one author per post; settle using returned post/user resources. With the explicitly configured daily meter, hashed IDs count once per resource type and UTC day; repeated calls retain their actual response counts for audit. Midnight-crossing requests are charged in full because their billing day is ambiguous. Failed/unsettled requests retain their full reservation. Historical reservations are not rewritten or silently credited; budget replacement requires owner approval and a recorded provider-spend observation. Before each model call, reserve for UTF-8 input bytes plus protocol overhead and the output limit; settle with reported token counts. Network errors, crashes and missing usage leave the full reservation committed, with no automatic release/retry. A response costing more than its reservation blocks further admissions under that budget pending owner review. Configure provider-side billing controls too: this ledger covers this worker's estimated API/model usage, not taxes, hosting, other clients or the provider's final invoice.

For web discovery, the source allowance counts basic Tavily credit units: one per search and one per group of five extraction URLs, reserved conservatively before the request. The example permits 120 credits/day, at most five/hour. It rotates one of three queries per cycle, requests up to 20 results, refreshes up to ten existing published/pending/held URLs (published first) and fills the 20-URL extraction cap with discovery candidates. Dropped posts are reconsidered when rediscovered with changed content or screening policy. This is bounded discovery, not exhaustive web coverage. Tavily billing/key limits are separate and shared with the daily incident researcher; the application never purchases credits or changes plans.

The worker uses `PGUSER=project_martian_radar_worker`, its own `PGPASSWORD_FILE`, and `npm run radar:worker`. `-- --once` performs one full cycle. Leave `MARTIAN_RADAR_INFERENCE_ENABLED=false` for an offline/no-model run. Enable it explicitly for classification, embedding and titles. Defaults are `MARTIAN_RADAR_REGION=us-east-1`, `MARTIAN_RADAR_MODEL_ID=us.anthropic.claude-haiku-4-5-20251001-v1:0`, and fixed `amazon.titan-embed-text-v2:0`. Grant a dedicated worker identity access to those models and required inference-profile destination resources; the Ask identity/model are unchanged. The [deployed IAM policy](../deploy/radar-bedrock-policy.json) records the current profile and model resources; adjust account and profile resources for another environment.

Source credentials are file paths: `MARTIAN_RADAR_TAVILY_TOKEN_FILE` for web discovery; `MARTIAN_RADAR_X_TOKEN_FILE`; `MARTIAN_RADAR_REDDIT_CLIENT_ID_FILE`, `MARTIAN_RADAR_REDDIT_CLIENT_SECRET_FILE`, `MARTIAN_RADAR_REDDIT_REFRESH_TOKEN_FILE`. Reddit also needs a descriptive `MARTIAN_RADAR_REDDIT_USER_AGENT` containing the responsible `/u/` account. RSS needs an approved enabled source, not a platform token. Keep all credentials out of source JSON.

Run the web app using its existing app role and `MARTIAN_RADAR_MODE=live`. Publication remains empty until the owner explicitly uses `controls --public on`. For intake, also set `MARTIAN_RADAR_INTAKE_ENABLED=true`, `MARTIAN_RADAR_INTAKE_KEY_FILE` (at least 32 characters), and the separate `RADAR_INTAKE_PGHOST`, `RADAR_INTAKE_PGPORT`, `RADAR_INTAKE_PGDATABASE`, `RADAR_INTAKE_PGUSER=project_martian_radar_intake`, `RADAR_INTAKE_PGPASSWORD_FILE`; then enable `controls --intake on`. The web process never receives reviewer, worker or owner credentials.

## Review commands

Use the reviewer credential for these commands. `queue`, `inspect`, `status` and `intake` read; all mutations require `--actor` and `--reason`. Run private-content commands only in a private operator session.

```sh
npm run radar:manage -- queue --decision held
npm run radar:manage -- queue --decision all --source SOURCE_ID
npm run radar:manage -- inspect POST_UUID --content
npm run radar:manage -- reprocess POST_UUID --revision 1 --clear-flags uninspected-media --actor YOUR_NAME --reason 'Inspected attached media'
npm run radar:manage -- approve POST_UUID --revision 2 --actor YOUR_NAME --reason 'Reviewed complete source'
npm run radar:manage -- primary POST_UUID --revision 3 --actor YOUR_NAME --reason 'Reviewed primary evidence'
npm run radar:manage -- drop POST_UUID --revision 4 --actor YOUR_NAME --reason 'Outside agent security scope'
npm run radar:manage -- remove POST_UUID --revision 5 --actor YOUR_NAME --reason 'Author removal request verified'
npm run radar:manage -- link-cluster CLUSTER_UUID --record INCIDENT_ID --actor YOUR_NAME --reason 'Matched reviewed incident'
npm run radar:manage -- unlink-cluster CLUSTER_UUID --actor YOUR_NAME --reason 'Record match withdrawn'
npm run radar:manage -- intake --content
npm run radar:manage -- resolve RECEIPT_UUID --actor YOUR_NAME --reason 'Completed private review'
npm run radar:manage -- status
```

These UUIDs/revisions are placeholders, not a sequence to run blindly. Always inspect the current revision. `reprocess` explicitly overrides the rules cutoff; only named flags are cleared. It does not publish, and Claude can still drop/hold. Direct approval requires a valid classification, no unresolved flags and current source verification. Primary-source status is a human declaration, never automatic from Claude's kind. `inspect` suggests current incident IDs sharing an exact canonical evidence URL; it never links automatically, and semantic match suggestions are not implemented. Create/review an incident through the existing contribution/publication workflow before linking it.

Queue rows include source ID/publication mode; `status` includes counts by source/decision, pagination backlog, last complete collection, provider pauses and each budget's committed amount, unsettled reservations and reported resource/token counts. Owner controls also include `stop-budget BUDGET_ID` and `resume-provider x|reddit`, each with `--actor`/`--reason`. Resume only after checking the provider reset/access state; it does not reset daily or monetary usage. The operator should sample accepted, held and dropped items privately. The proposed 100-item relevance review and seven-day pilot have not yet been completed.

The October 5 pre-change diagnostic found exactly one enabled Google Security RSS source and three correctly dropped articles, explaining the empty feed. A proposed expansion of the manual RSS list was superseded by the user's request for application-owned hourly discovery. ## API and operational bounds

`GET /api/radar` returns a versioned sample or live response. Live accepts `source=all|x|reddit|linkedin|wild`, `q` up to 120 characters, `sort=latest|popular` (API default latest, UI default popular), `limit` 1–50 and an opaque cursor. It includes source health, current publication ID, posts, top clusters and next cursor. Source health adds `publication_mode`, `last_complete`, `resume_after`, `manual_pause`, `kind` and a public `name`; search queries and extracted context are not exposed; `last_complete` is a completed collection time, not a promise of full provider coverage. Popularity cursors bind their ranking time and sort; changing sort requires restarting pagination. Posts add `author_verified`, `edited`, `saved`, `checked_at` and `source_current`, and URL entities can include the provider's `display` label. LinkedIn returns no public posts. `GET /api/radar/posts/:uuid` and `/api/radar/clusters/:uuid` return only currently visible source detail; unavailable objects return 404. `POST /api/radar/submissions` accepts a LinkedIn `url`, pasted `text` and optional `contact`; `/api/radar/reports` accepts `post_id`, `reason` and optional `contact`. Intake is disabled in production and these routes return 503; if explicitly enabled separately, successful intake returns 202 plus a receipt. No public route exposes raw held/dropped content, model explanations, budgets or queue contents.

Collection is intentionally bounded: production X `selection: popular` requests one relevance-ranked page from the last 24 hours each cycle, independent of prior pagination. Optional `selection: recent` retains chronological cursor/backlog behavior and seven-day window checks. Page sizes are 10–100, refresh limits 1–100, and there are at most 200 RSS entries, 40 vetting and 40 embedding jobs per pass, 2,000 duplicate candidates, 5,000 visible clustered posts and 500 detail posts. Aggregation/detail capacity errors do not return partial statistics. Latest X edit IDs trigger a separately metered lookup after hiding obsolete text. The adapter collects only the root post and its author; no referenced-post or profile lookups are used. Reddit retains boundary-overlap pagination and an explicit gap error. Actual busy-listing completeness and real provider edit/delete transitions remain unverified.

X/Reddit response reset headers and `Retry-After` persist a shared platform pause across restarts. HTTP 429 without a valid reset requires operator resume. There is no immediate retry. Fresh-content expiry continues during pauses, missing credentials or budget exhaustion. Saved history remains available, and the page distinguishes a spending pause from a genuinely empty feed.

Except for web discovery’s credit-unit allowance, daily request allowances count admitted HTTP calls, including failed requests; Reddit OAuth renewal counts against the requesting source. The shared model allowance counts admitted classification, embedding and title calls, including failures. The new spend ledger is a separate constraint, and budget-denied calls consume neither money reservations nor daily calls. `status` exposes source errors and worker heartbeat; `--health` checks the worker's local heartbeat. The hourly release configures a separate daily model-call ceiling and a dated monetary allowance; see the deployment guide for the active limits.
